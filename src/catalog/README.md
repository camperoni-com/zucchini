# Catalog

## Overview

Generates the step catalog: every step a contract can use, as JSON for agents and tools and as Markdown for people.
The catalog is built from the step definitions themselves (see [`src/steps`](../steps/README.md)), so it can't drift
from the code. This directory only builds and formats the catalog; the `zucchini` command (`src/cli/catalog.ts`)
decides where it is written.

## Interface

All of these are exported from the package entry (`src/index.ts`).

- `StepSource`: `'library' | 'project'`.
- `CatalogEntry`: `{ keyword, wording, parameters, meaning, example, source, discouraged? }`. `parameters` lists the
  wording's parameter types in order, for example `["string", "string"]`.
- `Catalog`: `{ generatedBy, steps }`, where `generatedBy` is the command that regenerates the catalog.
- `buildCatalog({ library, project?, generatedBy })`: returns a `Catalog` with the library's steps first, then the
  project's, each tagged with its `source`.
- `catalogToJson(catalog)`: the catalog as JSON with 2-space indentation and a trailing newline.
- `catalogToMarkdown(catalog)`: a `# Step catalog` page with a step count and two sections, `## Library steps` and
  `## Project steps` (an empty section says `None.`). Each step gets a `### <keyword> <wording>` heading, its meaning,
  a `**Discouraged:**` line when it has one, its parameters and its example.
- `discouragedText({ reason, instead? })`: `"<reason> Use <instead> instead."`, or just the reason when there is no
  `instead`. The linter in `src/contracts/lint.ts` uses the same text for its warnings.

## Invariants

- `buildCatalog` throws `The example of "<wording>" doesn't match its wording: "<example>"` when a step's
  `example` doesn't match its Cucumber expression, so every published example is a real, matching step.
- Steps keep their given order within each source, and library steps always come before project steps.
- `discouraged` appears on an entry only when the step has one; other entries have no `discouraged` key.
- The Markdown says it is generated by `generatedBy` and must not be edited by hand. Regenerate it rather than
  editing it.
- Parameter types come from `compileSteps` in `src/steps/expressions.ts`, compiled against one shared
  `ParameterTypeRegistry`.

## Side Effects

- None. Every function is pure and returns a value or a string; writing the files is left to the caller
  (`src/cli/catalog.ts`).

## Verification

- Run: `npm test` (all unit tests), or `npx vitest run src/catalog` for this directory's tests only.
